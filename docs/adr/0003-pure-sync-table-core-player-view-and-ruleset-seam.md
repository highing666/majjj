# 纯同步对局核心、类型级视角隔离与轻量 Ruleset 边界

为了让核心规则引擎同时服务于局域网实时对局、前端 2D 演出与离线高吞吐强 AI 自博弈评估，且在未来扩展川麻/日麻时不致推倒重来，我们决定将 `mahjong-core` 设计为 **100% 纯同步、显式随机种子驱动、无 I/O 与无时钟的对局状态机**，以 **「权威内部事件日志 + 按座位投影 `PlayerView` / `PlayerEvent`」** 作为唯一事实来源，并采用 **轻量策略 Trait `Ruleset`（预留`吃`动作槽位、聚焦标准 4 人单终局小局流程）** 隔离玩法差异。

## Considered Options

- **在 `mahjong-core` 内嵌房间大厅、人类/AI 身份与操作超时时钟**：会把网络会话、准备流程、AI 异步调度与演出停顿耦合进规则内核，导致 `mahjong-ai` 离线万局自博弈和确定性种子回放被迫背负异步运行时与房间状态包袱。
- **v1 即在状态机内核预埋川麻/日麻复杂流程骨架**：在内核提前引入可插拔开局前子阶段（换三张/定缺）、胡牌后不终局的活跃座位循环（血战到底）与泛型规则状态包，会让未排期的未来玩法把复杂度提前转嫁到 v1 状态机与前后端类型契约上。
- **直接向 `mahjong-ai` 或前端共享完整权威 `TableState`**：依赖调用方自觉不读取牌墙与他家暗牌存在结构性泄密/作弊风险；且仅靠全量状态差分难以直接驱动 2D 出牌演出与音画事件钩子。

## Consequences

- **核心零身份与零时钟感知**：`mahjong-core` 只认识四个座次（东南西北），不区分人类与 AI、不内置超时倒计时；房间大厅、人机编排、局间 AI 自动确认（`ConfirmNextHand`）以及打牌节奏停顿全部归属 `mahjong-server`。
- **类型级防作弊与隐藏响应窗口**：`mahjong-ai` 与前端只能消费经 `project_view` / `project_event` 投影后的 `PlayerView`（含权威 `legal_actions`、立牌/摸牌分离、完整牌河手切/摸切轨迹）与 `PlayerEvent`（带单调 `seq`），响应等待态绝不向无权响应的座位泄露他家是否正在考虑鸣牌或胡牌。
- **静态分发兼顾运行期切换**：核心采用泛型 `Match<R: Ruleset>` 保障离线搜索零虚表开销，并配套轻量 `AnyRuleset` 枚举包装供 `mahjong-server` 未来按房间切换玩法；通用结算账单（`ScoreItem { code, label, fan }`）保证前端结算页零结构改造兼容未来新番型。
- **未来复杂玩法的显式演进前提**：扩展日麻时可在现有 4 人单终局内核上补充立直/宝牌等规则状态；若后续排期引入川麻「血战到底」（胡后继续打与换三张/定缺），届时需有意识地扩展状态机阶段与终局循环，而非将其硬塞进 v1。
